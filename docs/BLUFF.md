# Bluff — bluff-original-exact-v1

Richard Borg의 Ravensburger Bluff 기본판을 구현한다. 현금·칩·결제·보상은 없다.

규칙 출처: [Ravensburger 원작 설명서 스캔](https://m.brettspielwelt.de/pdf/Bluff.pdf), 인쇄 쪽수 2–7 (PDF 2–4쪽). 원문/이미지는 프로젝트에 복제하지 않는다.

- 2–6명, 5개씩, 눈 1–5와 ★. 일반 눈 계산에는 ★ 포함, ★ 선언에는 ★만 포함.
- 선언 순서: 숫자 1 → ★ 1 → 숫자 2 → 숫자 3 → ★ 2 → 숫자 4 … → 숫자 19 → ★ 10 → 숫자 20. 같은 숫자 개수에서는 눈 1→5로 상승한다. 숫자 최대 20, ★ 최대 10은 원작 보드 끝이다. 남은 주사위보다 높은 선언도 가능하다.
- 실제<선언: 선언자가 차이만큼 잃는다. 실제>선언: 도전자가 차이만큼 잃는다. 보유량까지만 제거한다.
- Exact: 선언자를 제외한 모든 참가자가 1개씩 잃는다. 제3자의 마지막 주사위도 제거되며 동시에 탈락할 수 있다.
- 판정의 승자(부족하면 도전자, 같거나 많으면 선언자)가 다음 라운드를 시작한다. 남은 주사위를 모두 새로 굴린다. 최후 1명이 승리한다.
- 최초 선은 별도 5개 굴림 합계 최고인 참가자. ★는 숫자가 없어 0으로 합산, 동점 참가자끼리 재굴림하는 디지털 타이브레이크를 명시적으로 채택했다. 초기 결정용 주사위와 실제 비공개 주사위는 별도로 생성한다.

주의: BrettspielWelt 웹 설명에는 ‘패자가 다음 선’, ‘Exact에서 제3자의 마지막 주사위 보호’라는 온라인 변형이 있다. 이 프로젝트는 그 변형을 섞지 않고 링크된 Ravensburger 원작 규칙서를 따른다. 라운드 중 선택 재굴림 확장도 사용하지 않는다.

## 온라인 동작

기존 방, Ready, 초대 코드, PeerJS 연결, session token, 채팅, IndexedDB, JSON 복구를 그대로 사용한다. 대기실 Host가 게임을 변경하면 참가자 Ready가 초기화된다. 7명 이상 방은 Bluff로 변경할 수 없다. Yacht는 계속 최대 8명이다.

Host만 다음 라운드를 연다. 공개 판정 화면을 읽을 시간을 주기 위한 UI 단계로, 선 플레이어 자체는 판정 승자이다. 탈락자도 Host 역할·관전·채팅은 유지한다.

연결 단절은 기권과 다르다. 단절 시 상태를 그대로 유지하며 기존 인증으로 재접속한다. Host 종료 시 기존 저장 문서로 같은 코드에 복구한다. 자동 Host migration은 없다.

명시적 퇴장 또는 Host의 오프라인 참가자 기권 처리 시 주사위가 0이 된다. 숨겨진 라운드 도중의 기권은 현재 선언을 취소하고 생존자의 주사위를 다시 굴린다. 현재 차례의 기권이면 다음 생존자로 이동한다. 판정 후의 기권은 이미 공개된 결과를 바꾸지 않는다. 마지막 생존자를 즉시 승자로 확정한다. 이는 온라인 퇴장에 대한 프로젝트 규칙이며 원작의 정상 판정과 구분한다.

## 비공개 정보 경계

`engine.publicState(game, playerId)`는 명시적 필드 목록으로 플레이어 뷰를 만든다. 현재 라운드 전체 dice 맵은 전송하지 않으며 자기 ownDice만 전송한다. 판정 후 result.dice와 과거 판정 history는 공개된다. publish, heartbeat 응답, stale revision 응답, replay 응답, 재접속 모두 동일한 필터를 통과한다. 익명 연결에는 상태를 전송하지 않는다.

Host는 전체 상태를 관리하는 신뢰된 참가자이다. Host의 개발자도구·IndexedDB·저장 JSON에는 전체 주사위가 있다. 참가자 간 비공개는 보장하지만 악의적인 Host에 대한 암호학적 공정성은 제공하지 않는다. JSON에는 기존 session 인증정보도 있으므로 개인적으로 보관한다. AI에는 자기 플레이어 뷰만 전달한다.

전송 프로토콜은 2로 올려 구버전 화면이 새로운 게임 상태를 잘못 해석하지 않게 한다. 기존 저장 버전과 초대 코드 주소는 유지한다. 배포 후 모든 참가자가 새로고침하면 된다. 추가 계정·API 키·외부 서비스는 필요 없다.

## 파일과 검증

새 게임의 rules / engine / ai / validate / ui를 `src/games/bluff/`에 추가했다. 공통 변경은 registry 등록, 게임 선택, 상태 투영, 저장 validator 연결, 화면/AI 분기뿐이다. Yacht 엔진·AI·점수 코드는 변경하지 않았다.

`npm test`: 규칙, 선언 전체 순서, Exact 제3자 탈락, 턴, 기권, 저장 무결성, AI 완주, 모든 네트워크 상태 전송 경로 비공개 검증 + 기존 Yacht/방 테스트.

기존 `npm run test:e2e`에 Bluff 시나리오를 연결한다. 같은 WebRTC 테스트 환경에서 혼자 + AI, 6개 브라우저, 대기실 게임 전환, 정원, 준비, 모바일, 채팅, Guest 새로고침, Host 저장 복구, 상향 선언, 판정, 탈락, 최후 1명을 확인한다. 기존 Yacht 혼자/8인 96턴 검증도 그대로 실행한다. 기존 Pages workflow가 배포 전과 실제 배포 URL에서 두 게임을 검증한다.
